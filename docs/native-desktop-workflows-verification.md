# Canvepp 0.6.12 桌面工作流验收记录

Windows 在 `.22` 的真实桌面会话中运行与安装包一同构建的程序。测试使用单独的资料库、浏览器配置和合成文件。三击空格测试通过 Windows 输入队列送达按键，并检查助手窗口是否成为键盘前台。托盘测试使用系统返回的通知图标位置进行实际点击。

## 后台运行

- 关闭主窗口后，窗口隐藏，进程仍在。此时在另一应用内三击空格，助手取得焦点，主窗口仍保持隐藏。
- 左键点托盘图标恢复同一个进程的主窗口。再次启动 Canvepp 也会恢复该窗口。
- 右键托盘实际显示「打开 Canvepp」和「退出 Canvepp」。点击退出，进程以状态码 0 结束。

## 三击空格

| 场景 | 实机结果 |
|---|---|
| Canvepp 画布、设置、全部画布、全部图片、回收站 | 助手出现并取得键盘前台 |
| Chrome 普通页的输入框、地址栏及 F11 全屏页 | 助手出现并取得键盘前台 |
| 资源管理器的已选文件列表和地址栏 | 助手出现。文件预览与三击可以在同一入口使用 |
| 记事本、终端、带可编辑控件的 Win32 窗口 | 助手出现并取得键盘前台 |
| 单击、双击、超时连击、长按及重复事件、Ctrl + 空格、连击期间切换窗口 | 均未触发 |
| 游戏识别 | 使用 Unity 窗口类的测试窗口验证跳过。系统安全桌面和没有可识别标记的网页游戏不在验证范围内 |

通过场景从首个空格到助手成为前台约 250–282 ms，含测试里的三次按键间隔。最终构建中实际关闭三击空格再开启，验证禁用与恢复均生效并写入资料库。关闭资源管理器预览后，三击空格仍能唤起。

## 批量与会话

多张时可在生成按钮前选择并行。默认串行，写入资料库后继续沿用。关时按批逐张执行，开时一批最多同时执行四张，应用同时运行的生图请求也限制为四个。受控 app-server 验证三张都已提交后才释放输出，三张都保存了独立结果。测试覆盖串行顺序、切换持久化、旧会话查回及临时会话断线后恢复本机结果。

最终构建中以三张创作实际打开并关闭并行开关，核对两次都写入了本地设置。[并行开关实机截图](../artifacts/canvepp-0.6.12/parallel-switch.png)

使用随包的 Codex CLI 0.169.0 单独验证临时会话没有出现在普通列表。此轮生图测试使用受控输出，没有消耗账户生图额度。[生图会话占用方案](native-generation-session-lifetime.md)

Go 全量测试、`go vet` 和此次改动涉及的重点竞态用例通过。Windows 与 Mac 均已打包。验收后两台机器的正式安装均为 0.6.11，Windows 的测试程序已退出并归档。[构建校验值与场景记录](../artifacts/canvepp-0.6.12/verification.json)
