# 本地服务实现说明

Canvepp 使用同一 Next.js Node 进程提供画布接口、SQLite 状态和单节点执行服务。支持本地模拟、手动回填和原生 Codex 宿主任务；独立 Images API 默认关闭。本地后端测试没有向 Images API 或原生图像工具发出真实生成请求。

## 运行与持久化

默认数据目录为项目下 `.data/`，可在启动前用 `CANVEPP_DATA_DIR` 指定其他本地目录。目录和图片文件分别采用 0700、0600 权限，SQLite 主文件为 0600；使用 WAL 和事务保存状态。数据库保存项目图、版本、预览、运行、Job、事件、确认去重、预算与本地会话。数据库是权威来源，浏览器刷新不会创建新 Run。

图片按 SHA-256 内容寻址，先写临时文件再原子改名。AssetVersion 只含公开元数据，内部文件位置单独存储，接口和导出包不包含服务器路径。原始图片读取和供应商发送前重新校验 hash；损坏文件阻止读取或发送。缩略图按需生成，最长边 480 像素、WebP，保存在 `thumbnails/{sha256}.webp`，不作为资产版本，也不代替原始文件。首次缩略图解码最多两个并行，随后从缓存读取。

图保存通过 `expectedRevision` 乐观锁检查，冲突返回 409。业务配置版本与节点 ID 由领域层维护；移动和改名不改变运行输入 fingerprint。`layoutRevision` 仅在位置或视口确实改变时递增。选图是显式操作：新任务成功只追加结果，绝不自动替换节点已选版本。撤销图状态不删除历史任务或账本。

## 执行模式

- **模拟**：在本地用确定性图形与图片变换生成 PNG，带有 `MOCK · LOCAL SAMPLE` 标识。用于验证流程，不表示真实模型效果。
- **原生 Codex**：预览冻结 `codex-native-imagegen` / `codex` 输入，确认后进入 `awaiting_host`，不进入模拟或 API 队列。每次一张；尺寸和质量是意图，不能保证精确。它消耗 Codex 账户额度，美元 API 账本记录为 0，不表示额度无限或不消耗。
- **手动**：确认后得到 `awaiting_import` Run，用户在外部界面生成、上传并明确确认来源。回填创建独立 AssetVersion 元数据，原导入版本不被改写；来源为“用户确认”，不宣称 API 已验证。
- **API**：适配器实现官方同步 Images API 的生成与编辑请求，但默认关闭。本版缺少已核实的完整请求费用上界，服务端拒绝真实 API 预览和提交；手填单价、到期日或启用开关不能绕过。后续启用需要补齐已核实定价计算、账户/额度/密钥/预算确认及用户真实调用授权。

API 适配器只编码已核实的 `gpt-image-1.5` 参数集合。密钥仅从服务端 `OPENAI_API_KEY` 读取。组织和项目 ID 在 RunPreview 中冻结并用于出站请求头，不借用 ChatGPT cookie、登录令牌或原生生图额度。编辑素材被规范化为真正的 PNG 文件后提交。该适配器没有声称支持供应商查询、供应商幂等或可靠取消。当前型号和价格复核限制见 [定价模块](../src/domain/pricing.ts)，不能将参考输出单价当作完整请求费用。

## 提交、幂等和预算

`POST /runs/preview` 冻结解析后的提示词、参数、主图具体版本/hash、模型和账户标识，产生五分钟有效的只读预览。预览本身不会提交供应商。`POST /runs` 必须携带快照 hash、确认 ID 和幂等键；图版本、输入或估算变更要求重新预览。

Run、Job、初始事件、确认去重记录和预算预留在同一 SQLite 事务内创建。同一预览、确认 ID 或幂等键不会产生第二次提交意图；同一确认标识被用于其他预览时返回冲突。该保证仅覆盖本地服务，不等于供应商 exactly-once。

默认队列串行。已确认任务仍使用不可变快照，用户可以继续修改草稿；返回时按内容 fingerprint 标记 `draftChanged`。在此期间删除节点也保留返回图片及原 nodeId/Run 来源。

预算包括当前月已预留与已结算估计。估价由可信的服务端计算函数提供，预算设置不能自行制造上界。缺失凭据、额度未知或到期、价格复核失效、预算不足时阻止出站。供应商 usage 保留为记录；不能从 usage 可靠计算成本时，账本使用保守预留上界并明确保存为 `settled_estimate`，不冒充实扣账单。删除项目后匿名保留已消费月度总额，不能借删除重置预算。

## 原生宿主领取与回填

`GET /api/host/pending?projectId=...` 返回 `{runs}`，只列本地确认且未领取的任务。`POST /api/runs/{id}/host/claim` 接受 `claimId`、可选 `clientId` 和 `requestId`，在 SQLite 即时事务内领取；第一次返回 `canGenerate:true` 并转 `running`。同领取 ID、客户端与本地会话重读返回相同凭证及 `canGenerate:false`；其他领取者收到 409。重读不能触发第二次生图。

领取凭证只向领取者返回，数据库只保存其 hash；稳定派生使用的私有 HMAC key 保留在本地数据库私有表。凭证和私有表不进入 Run、诊断或导出。完成接口为 `POST /api/runs/{id}/host/complete`，multipart 字段是 `claimToken`、`requestId` 和 `file`；也可用 JSON 数组字符串 `assetVersionIds` 回填一张新导入素材。二者只选一种。相同结果的并发或重复写回只产生一个素材版本；不同结果冲突。版本来源标记 `codex`，原导入元数据保持不变，不自动采用输出。

`POST /api/runs/{id}/host/fail` 接受领取凭证、`outcome:failed|unknown` 与说明。状态未知时不允许重新领取生成；可以提交原任务迟到的已知结果。取消后仍保留迟到结果。重启保留未领取的 `awaiting_host`，已领取的运行改为 `unknown`，不重发。导入项目中的等待宿主历史改为不可执行的 `unknown`，必须创建新预览确认才能再次生成。

## 取消、崩溃和恢复

- 排队或等待手动回填时取消，未提交供应商并释放预留。
- 提交后取消只标记本地停止等待；保留取消请求标记，不承诺供应商已停止或退款。活跃工作进程收到迟到结果时继续入库并标记 `lateResult`。
- 网络中断、响应解析失败或不确定供应商异常进入 `unknown`，不自动重试，不释放预留。可用的供应商 request ID 保留用于对账。
- 服务启动扫描已排队、提交中或运行中的任务，转为 `unknown`（未领取的原生任务与等待手动导入保留等待状态），不会重新提交。尚未被记录的外部结果需人工核对；同步 Images API 没有在此实现可靠查询接口。
- 供应商结果返回后先保存暂存图片与 `staging/{runId}.json` 清单，再登记资产。若入库失败或此时进程退出，`POST /runs/{id}/recover` 只校验并读取暂存文件，不调用供应商。
- `POST /runs/{id}/reconcile` 仅接受 `unknown`，需要人工核对说明。`not_accepted` 明确确认未受理后释放预留；`charged_no_output` 确认已计费无可用输出后按保守上界结算。用户若要再次生成，需要重新预览并创建新 Run。

本地服务针对单进程、单人使用设计，没有多工作进程调度租约。不把服务进程恢复测试解释为突然断电或文件系统损坏的完整保证。

## 导入、导出与删除

图片仅接受有效静态 PNG、JPEG、WebP，单文件不超过 20 MiB、像素不超过 4000 万。文件签名与实际解码决定格式，不相信扩展名。`metadataPolicy=strip` 保存经过方向修正和元数据去除的副本，不另留原字节；`preserve` 保留原始字节。选择由用户决定。

项目 ZIP 包含 `project.json`、`runs.json`、`checksums.json` 与全部关联素材，保留历史与父版本关系，不包含密钥、会话、SQLite 或服务器路径。导出包会包含用户创作提示词与图片，应按用户文件保存。导入给项目、节点、运行和资产重新分配 ID，保留逻辑资产分组、hash 和来源关系；导入不产生生成请求。未知 schema 被拒绝，原包不被修改。

导入先检查文件数、压缩包/解压大小、路径穿越，再有界流式解压；素材重新解码并比对清单 hash。运行中和待对账项目不能删除；项目删除需显式确认和最新 revision，仅删除数据库引用及不再被其他项目引用的本地文件，不删除用户导出的备份。

## 本地访问保护与错误

服务默认绑定 `127.0.0.1`。`GET /api/session` 建立 HttpOnly、SameSite=Strict cookie；写入同时需要对应的 CSRF token 和 requestId。除只提供服务身份的 `/api/health` 外，所有资源读取也需要本地会话；`health` 在打开数据库前校验本机 Host/Origin，只返回 service、protocolVersion、根目录 hash 标识 rootId、instanceId 和 pid，不返回路径；服务校验 Host、Origin 和跨站 fetch 信息，不开放任意来源 CORS。密钥、完整提示词、图片内容和服务器路径不会进入默认诊断包。诊断包保留任务 ID、状态、事件、hash 和预算摘要。

错误区分 validation、authorization、quota、rate_limit、policy、provider_error、transport_unknown、storage_error 及冲突。供应商原始错误正文不会原样返回用户。查询或取消供应商任务不被隐含模拟为成功。

## 已验证与待验证

2026 年 10 月 29 日，完整项目的 7 组测试、60 个用例通过，TypeScript 检查通过。服务端覆盖真实本地 PNG 导入/生成/读取、不可变快照与版本、显式选图、重复确认、重启 unknown、取消与迟到结果、暂存恢复零重发、原子预算预留、手动回填、ZIP hash/路径检查，以及真实 Request/Response 的会话与 CSRF 边界。预算原子性测试仅在构造器内注入测试估价，不对外暴露这个能力；供应商测试全部替换 fetch，未进行真实调用。保存重开及旧窗口冲突各做了 10 轮确定性服务端验证。

浏览器交互、真实供应商质量与 usage/收费、宿主内嵌、真实用户独立创作、突然断电恢复，需各自的证据。本说明不把单元测试通过表述为这些场景已经验收。

2026 年 10 月 30 日，新增 13 个原生后端用例及 2 个 HTTP 用例通过；覆盖领取竞争、会话绑定、token hash、并发完成和恢复、迟到结果、节点删除、重启、来源克隆、导出凭证隔离与健康探测不创建数据。相关已有服务端、HTTP、项目删除和定价测试一并通过，TypeScript 检查通过。这里的图片由本地测试 fixture 构造，不是原生工具调用证据；实际消息队列、宿主执行和浏览器验证由各自联调记录说明。
