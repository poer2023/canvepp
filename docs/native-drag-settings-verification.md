# Canvepp Native 0.4.7 · 拖动与图片参数

日期：2026-11-06。原生 Go 1.27.3 / MyGo 0.7.4，Apple M4，1920×1080、60 Hz 显示环境；用户通过 UU 远程操作。合同见 [native-drag-settings-acceptance.md](native-drag-settings-acceptance.md)。

## 实施结果

- 图片直接按屏幕坐标提交 GPU 圆角裁剪，避免缩放后的裁剪在每次移动时生成并上传 CPU 蒙版。透明棋盘随图片尺寸保持正确比例。
- 拖动时保留当前编辑器，松手同步新选中图片的设置；坐标仍立即更新，一次拖动只形成一条可撤销操作。
- 删除左栏底部的图片设置按钮，保留应用设置；点击图片可以重新打开图片设置。
- 来源/创作标题移除竖条；比例为等尺寸 3×3 宫格，自由像素最后一项；宽高输入在下一行，删除步进按钮；1–4 张整齐排成一行。保留多参考图缩略图，删除重复说明。
- 部分数字或非法文本不写入草稿；固定比例联动宽高，两个方向都限制在 64–8192 px。没有调用生图，也未变更来源、任务、图片存储或会话路由。

## 性能证据与未通过项

完整原生帧的 CPU 采样包含 build/layout/paint/present，排除每次启动的前 5 帧。0.4.6 的 107 帧中，中位数 2.1 ms、p95 24.5 ms、最大 66.5 ms；最终直接绘制方案的 577 帧中，中位数 1.5 ms、p95 3.1 ms、最大 17.3 ms。两组交互样本数量及动作不同，不是严格 FPS 对照，更不能当作端到端输入延迟。

用户实际连续拖动记录到 423 个移动事件、404 个绘制样本。事件到达间隔中位数 16.69 ms、p95 50.09 ms、最大 124.37 ms；最后一个事件到绘制命令的时间中位数 0.37 ms、p95 0.76 ms；画面绘制间隔 p95 50.51 ms。停顿可以同时来自操作本身停留、输入到达节奏与显示链路；这份采样只证实处理已到达的事件很快，不能单独归因 UU，也不能证明用户主观手感已达标。

独立诊断副本通过公开 Metal drawable 回调观察实际呈现时间，但当前环境的 `presentedTime` 返回 0，无法据此测量显示端延迟。该呈现探针只存在于临时诊断构建，不进入正式应用；正常启动也不启用输入时序采样。

曾试验静态网格、侧栏和浮动面板的 GPU 层缓存，用户未感知改善，软件回退基准更慢且分配增加，已撤回。其主观对比还与后台 race 测试重叠，不能作为干净 A/B 结果。最终保留直接绘制方案，主观远程拖动流畅度仍待确认，不宣称“卡顿彻底消除”。

详细原始数据：`artifacts/native-drag-settings-20261106/native-frame-summary.json`、`direct-frames.log`、`direct-receipt.json`、`display-callbacks.log`、`benchmark-final.txt`。
