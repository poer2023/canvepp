# Canvepp 原生迁移验收合同

Objective: 将 Canvepp 做成 MyGo + Go 全原生桌面画布，优先低占用、连续流畅的交互，保全旧图片、提示词、参数、连线、历史与回收站。

Gate 0: 已检查当前真实界面（光与食物的练习，20 张卡片）、现有 SQLite/资源格式和 Codex stdio 协议。锁定 MyGo 0.7.4 原生 GPU UI，独立 native 目录；旧版和未提交改动保持可用。

Gate 1: 实现独立应用、兼容导入、本地持久化、图片画布、快捷键、参考图与生成参数、原生 Codex 执行、历史/回收站。后台生成保留不可变请求、线程/轮次回执及未知结果恢复，不自动重试生图。

Gate 2: 生成可运行的 macOS arm64 应用；运行有针对性的 Go 单测、竞态检查、性能基准及真实 GUI 验收。确认原库/原图未丢失；说明未经实机验证的平台。

## 界面合同

- 纯左右结构，参考 Zen 的紧凑侧栏：左侧集中项目、图片设置、历史、回收站与备份，右侧整块画布。取消可见顶栏及右侧设置栏。
- 顶部保留 28 px 透明窗口拖拽区，不显示标题或工具；系统窗口按钮留在左上角，画布不为顶栏让出整行高度。
- 图片默认仅显示图片或占位，悬停操作位于图片外；连线从左右边缘连接；透明背景用棋盘显示。
- 保留固定比例宫格、常显像素输入、1–4 张独立输出、多图参考缩略图；选中图片后在左侧编辑提示词，历史/回收站仍可切换。
- 支持平移/指针锚定缩放、最高 400%、框选/多选拖动、复制/粘贴、删除入回收站、撤销/重做、原图预览与下载。
- 保留系统文件拖入与原生文件选择器；文本框内快捷键不得误删画布内容。
- 原生启动无浏览器、WebView、React 或 Node 服务依赖。后台 Codex 是独立的生成运行时。
- 初次导入复制旧库数据和资源，独立数据目录；原库只读，失败不留下部分导入；旧生成请求仅作为历史，不能重放。

## 性能与数据约束

- 交互帧不进行磁盘 I/O、图片解码、全图 JSON 编解码或网络请求；操作结束后异步提交持久化。
- 仅绘制可见图片/连线；后台缩略图、去重、有限解码并发和有限缓存；高倍预览独立加载原图。
- 100 张图片的热缓存交互目标：本机 60 Hz 帧预算 16.7 ms；分别记录 CPU 场景/帧构建与真实显示表现，不混称 GPU 帧率。
- 记录进程 RSS、应用体积、冷启动表现、100/500 卡片 benchmark。任何未达到的指标必须明确报告，不使用“完美”作为未测结论。
- 一次拖动形成一条撤销记录；删除/恢复和批量粘贴保持图片、内容、关联边完整；取消或延迟返回仍保留结果。

## 验证

- 桌面原生窗口：1440×900 与 1100×740。无需移动 Web 适配。
- Go 单测与 race 检查覆盖坐标/选区/撤销、导入完整性、保存失败、任务不可重复执行。
- 真实电脑 UI 检查启动、拖动/缩放、多选、粘贴、回收站、中文输入、预览、重开保存；生成链路先做只读能力检查，真实生图仅在用户提交任务后执行。
- 证据写入 artifacts/native-desktop，验收报告必须列出未完成与未验证项。

Non-goals: 本轮不发布收费服务，不改订阅认证为非官方接口，不迁移或修改远端 .117，不删除旧实现和原始数据。

Stop conditions: 数据校验失败则停止该次导入；生成结果不明确则查询原轮次，不重新提交；框架能力不足则记录真实阻碍并继续可独立完成的部分。
