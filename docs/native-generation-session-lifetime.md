# Canvepp 生图会话占用方案

现有订阅生图为每张图片执行一次持久的 `thread/start`，再按提示词命名会话。一批四张图因此在 Codex 主列表中留下四条记录。恢复时凭会话和轮次查询原任务。

## 新生成

Canvepp 向当前 Codex app-server 请求临时会话（`ephemeral: true`），确认返回的会话也是临时会话，然后提交一轮生成。每张图仍有独立的上下文和结果归属。批量并行时也使用同一规则。应用通过本轮的完成事件取得图片，并立即把原图、批次、画布归属、模型和任务回执写入本地资料库。用户可以从 Canvepp 查阅这些生成记录。

订阅来源和所选模型沿用设置。使用 OpenAI Images API 的生图继续直接提交图片请求。摘要继续使用临时请求，主动发消息的创作助手保留可继续打开的画布会话。

## 中断与已有会话

临时会话随运行时关闭，之后无法通过云端历史查询。Canvepp 先检查本地资料库里是否已导入结果，再检查该轮已有的本机输出目录。只有找到能确认归属的单张图片才恢复结果。找不到时保留待确认状态，查询操作不会再发一次生成请求。

旧任务仍用保存的会话和轮次查询结果。已有的 Codex 长期会话保留原样，方便继续打开或手动归档。

## 验证

用交付包同版的 Codex CLI 0.169.0 在独立测试目录打开临时会话，普通 `thread/list` 返回零条记录，返回的会话路径为空，磁盘上也没有生成会话历史。该版本的临时会话不支持 `thread/turns/list`。回归测试通过完成事件导入图片，并覆盖断线后本机恢复、恢复时避免重新提交以及查回旧任务。
