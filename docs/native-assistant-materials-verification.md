## 助手

- 原生浮动输入条，无占位符；关闭按钮和 Esc 隐藏，保留未发送草稿与附件。输入自动折行增高，达到上限后内部滚动。Enter 发送，Shift+Enter 换行。
- 流动渐变边框在窗口可见时以 30 fps 更新；关闭停止请求动画帧。修复 MyGo TextArea 默认最小 80 px 导致的短输入框和附件截断。
- 系统文件选择器及拖入支持最多 8 个、每个 20 MB 的附件。图片通过 Codex 的 `localImage` 传入。文档后台读取并保存不可变副本，再把实际文字传入会话；不是仅发送文件名。
- PDF 使用系统 PDFKit；Word / RTF / ODT 使用本地 textutil；普通 UTF-8 文本直接读取。最多 128 KB 文本、PDF 最多 200 页，不静默截断；无法读取、加密和纯扫描内容明确提示。文档图片与排版未解析，并在附件提示和发给模型的数据中明确注明。
- 使用当前 ChatGPT 登录及原有 `gpt-6-luna`，不换模型、不调用独立 API，不生成新图片。

## 0.6.8 本机登录与额度

Windows x64 安装包已安装到 .22 的当前用户。通过桌面和开始菜单可打开 Canvepp。安装版和 macOS Apple 芯片签名包在 PATH 仅含系统工具时，均通过随包 Codex 识别已有 Pro 登录和生图能力。.22 的订阅模型列表包含 `gpt-6-luna`。

空白凭据目录在 macOS 取得 OpenAI 浏览器授权入口，在 .22 识别到 Windows 保留了 1455 端口，随后取得官方设备码。两次检查都在取得授权入口后取消。新账号在浏览器中的本人确认仍需手动完成。

在 .22 实际点击生图使用 API、摘要使用订阅，关闭并重新打开应用后，两项选择仍正确。独立切换摘要后已恢复测试前的选择。Windows 凭据库在第二个进程中可以恢复测试密钥。安装环境请求官方 API 得到预期的无效测试密钥响应。

测试服务覆盖无参考图生成、多参考图编辑、摘要、凭据和配额错误、已提交结果不明确，以及中断后重新关联已落盘的图片。供账号实测时，用户在设置中保存自己的 API Key 后，可按两项偏好发起请求。

OpenAI 将既有本机或开源应用的 Codex App Server 认证与商业、托管服务的接入分开规定。商业应用可使用官方 API，或申请自己的 Sign in with ChatGPT 客户端。[官方认证说明](https://learn.chatgpt.com/docs/app-server#auth-endpoints)；[申请客户端](https://developers.openai.com/siwc/request-client-id)。
