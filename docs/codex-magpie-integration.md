# Codex 与 Magpie 接入说明

更新于 2026-11-05。

## 独立打开画布

本地服务运行时直接打开画布。首次进入可以新建画布，之后从顶栏切换或通过专属地址打开。插件的打开工具会按需启动或复用本机服务，提供旧会话标识时仍可定位原画布。

## Codex 原生生成与记录

1. 画布冻结提示词、目标像素、按序排列的参考图和输出张数。用户确认后，在一个 SQLite 事务里创建结果卡片及每张图的独立任务。
2. 本地后台向官方 Codex App Server 检查 ChatGPT 登录和原生生图能力，为画布打开或复用专用执行会话。每个已确认任务只提交一个轮次，执行只使用本次快照。
3. 后台把原生工具返回的图片与会话、轮次、任务关联，校验文件并回填。操作页可关闭，本地服务需保持运行。修改过的卡片及取消后才收到的图片仍可在历史中找到。
4. 历史按生成批次组织。展开记录可定位结果、对照目标和实际像素、查看参考图，或打开对应的 Codex 会话。会话归档或轮换后，旧记录保留原链接。本地素材与快照可独立查阅。
5. 中断后按原轮次或唯一的任务标记读取执行记录。已收到文件但写入中断时从本地暂存恢复。未取得结果时允许继续核查，人工重新发起生成需要新的预览确认。

旧版已经确认的会话交接任务沿用原领取协议。恢复备份只带入素材和历史，新的生成需要在目标画布重新确认。

## 独立 Images API

Images API 是另一条执行通道，仍被模型与费用校准门阻断。没有经过验证的模型能力和总请求费用上界时，即使配置密钥、预算并打开开关，也不能提交真实请求。Codex 原生模式不需要借用这套 API 凭据。

API 的预算预留、供应商未知状态与人工对账继续适用于 API 通道；不能把这套美元结算描述用于 Codex 账户额度。后续启用真实 API 需完成相应能力、费用校准及明确授权下的最小真实调用验收。

## Magpie 尚未接入

本轮没有添加 Magpie provider，也不会在原生任务失败或未知时自动转交 Magpie。此前在 2026-10-29 的只读核查中，本机图像 MCP 曾列出生成、编辑相关能力；这只是候选接入证据，不证明 Canvepp 已使用该服务或完成真实生成。

后续若单独接入，需要按实际安装版本核验工具 schema、图像模型、账户与计费来源，并明确记录供应商及输出来源。聊天路由名称或支持图片输入，不能证明该路由本身是生图模型；Magpie 通道也不能统称为 Codex 额度或免费。本轮不改变 Magpie 配置、上游凭据或模型路由。

## 参考与验收边界

当前实现的执行流程以仓库中的 `local-service.mjs`、`canvas-agent.mjs`、MCP 工具、画布后台执行器及原生任务状态机为准。宿主安装、自动准备依赖、CLI 投递、真实原生生图与回填应分别留有实际证据；未完成的项目不能用代码实现或模拟响应替代。
