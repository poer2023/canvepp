## 浏览器实际操作

1. 初次加载六节点示例；明确运行一个编辑节点，收到一张带 MOCK 标记的图片。
2. 历史中将原图与新图加入对比；切换滑动对比并操作滑块。
3. 明确采用生成版本，输出节点显示该版本；新手动结果到达后旧选择仍保持。
4. 创建手动任务，上传测试 PNG，填写来源说明并确认，成功关联独立结果版本。
5. 从旧版创建三个新分支节点；撤销、重做、再撤销，最终回到六节点，任务仍是两条。
6. 刷新后六节点、所选资产版本与两条任务保留，没有新增生成请求。
7. 从 UI 导出 ZIP，再由 UI 导入；四个资产版本 hash 全部一致、两条任务来源恢复。删除本次测试导入的副本，原项目素材仍可读取。
8. 1440×900、1024×768、390×844：页面无横向溢出；属性栏可收起；缩放及尺寸变化后六节点可见。

浏览器发现并修复：Next 内部 URL 与实际 Host 别名导致会话 403；不稳定的选择回调导致 ReactFlow 重渲染循环；受控节点丢失 measured 尺寸导致窗口变化后节点隐藏；开发热重载导致模块级 CSRF 状态丢失。

另外对独立的 100 节点 / 150 连线测试项目做了性能复测：全图输入改为批量解析，选区变化使用缓存，未变卡片跳过渲染。40 次合成点击从事件派发到选中 DOM 状态更新的 p95 为 22.6 ms、最大 24.7 ms；100 个节点可见，期间无捕获到的运行错误。测试浏览器空闲 `requestAnimationFrame` 间隔约 1000 ms，因此此数据仅证明 DOM 提交延迟，不能等同于绘制帧率或全交互 p95。临时性能项目测试后已删除。
