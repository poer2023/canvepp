# Canvepp 图像节点画布

一个本地优先的图像创作工具。以图片为中心：新建或导入一张图片，选中后直接在侧栏填写提示词和参数，预览确认，再比较和采用结果版本。项目与任务保存在 SQLite，图片保存在本地。默认使用 **Codex 原生模式**，消耗 Codex 账户额度；模拟模式产生的素材会单独标记。

## 打开画布

本地服务运行时，在浏览器直接打开 [Canvepp](http://127.0.0.1:3210/) 即可创作。在 Codex 中说「打开 Canvepp 图像画布」也可以由插件准备依赖、启动或复用本地服务。首次准备需要 Node.js 22+ 及可下载依赖的环境。

顶栏的「画布」菜单可以新建、切换画布。浏览器记住最近打开的一张，也支持收藏每张画布的专属地址。旧会话入口仍指向已有作品。

默认服务地址为 `http://127.0.0.1:3210`，只监听本机。启动器核验服务身份和项目目录，避免把其他进程当作 Canvepp 复用；端口冲突时会报告错误。

数据默认保存在项目的 `.data/`，可通过 `CANVEPP_DATA_DIR` 指定绝对目录。该目录不进入 Git 或插件包。保留此目录即可保留项目；导出项目 ZIP 可用于备份和迁移。

## 完成一次创作

1. 点击「新建图片」从文字开始，或「导入图片」上传 PNG、JPEG、WebP（最多 20 MB）；也可直接把文件拖到画布。
2. 点击图片卡片，在右侧输入想生成的画面或修改要求，选择常用比例，或输入自定义宽高像素。不需要文本卡片、参数卡片或连线。图片默认只展示画面，悬停或键盘聚焦才在图片外侧显示名称与操作框，不遮挡画面。
3. 在参数区选择 **1–4 张**。单图生成多张会创建并排的独立结果卡片；框选 **2–8 张**图片时，右侧切换为多图参考面板，可调整编号顺序、移出参考、填写组合提示词，并选择输出数量。比例宫格和像素输入保持一致，原图提示词不被批量覆盖。
4. 点击右侧生成按钮，确认冻结的提示词、全部参考图、尺寸与张数。结果卡片在来源旁展开，以曲线连接；已有卡片与图片保留。Codex 原生多张输出会拆成多个单张任务，每次领取只允许一次原生生图，不把张数参数当成单次工具支持的批量数量。尺寸作为意图传递，实际像素以回填为准。
5. 本地后台使用已登录的 Codex，通过 App Server 在这张画布的专用执行会话里依次生成，每张图对应一个独立轮次。关闭页面后，本地服务继续处理已确认的任务。
6. 本次明确创建且未编辑的结果卡片自动显示首次回填图片；被改过、删除或取消的结果只保留在图片库，不覆盖草稿、不复活卡片。已有卡片的单张运行仍由用户选择采用版本。点击左侧「历史」的「图片」页，在两列缩略图中找图，展开底部版本后比较并明确「采用」，原图与旧版都保留。「从此继续」创建一个保留选定图片的独立分支，提示词和参数仍在该图片侧栏。
7. 画布可放大到 400%；高倍率切换原图。大图预览可选择适应、100%、200%、400% 并滚动查看细节。在侧栏或大图预览中导出图片，无需额外输出卡片。顶部「备份 → 导出画布备份」保留整个画布的素材、版本、快照和校验清单。

尺寸预设包括 1:1、4:3、3:4、3:2、2:3、16:9、9:16、21:9。比例宫格下方始终显示宽高像素，固定比例时编辑任一边会联动另一边（取整到像素）；最后一项「自由像素」可独立编辑宽高。宽高为 64–8192 的整数，总像素不超过 3200 万；无效值会提示并阻止运行。文件信息、导入策略与当前版本默认折叠；侧栏不展示节点 ID、文件指纹等诊断信息。

当前示例只包含图片与待创作的图片占位卡，编辑和导出直接围绕图片操作。示例整理保留原图、当前版本、历史任务和有效输入，并先保存原图结构与来源备份。用户已有旧项目不自动迁移，仍按原有连接解释；侧栏会注明旧连接的输入来源，选择「独立编辑」先复制当前有效值，再仅断开该输入连接。新建图片直接使用自己的侧栏设置，不提供独立提示词、参数、编辑或输出节点的新建入口。

编辑、连线、移动、保存、刷新和撤销均不会提交生成请求。输入发生变化时，下游旧结果仍可查看，并标记为基于旧输入。运行中的草稿可以继续修改；已提交快照保持不变。已确认的新结果卡片会显示首次回填的图片。

多窗口编辑会自动合并不同节点及不同字段的修改。只有同一字段同时改成不同内容时，才显示双方内容供选择，不再要求重载或复制整份画布。未保存草稿在各窗口独立保留，刷新后恢复；平移、缩放和选择不会制造项目版本，400% 查看状态也由当前窗口单独记住。同步其他窗口的修改后会重置本窗口的撤销历史，避免旧的整图快照覆盖新修改。

多选复制固定复制时的节点、图片版本与连线；之后修改或删除原节点也不会改变剪贴板内容。重复粘贴按次偏移，缺失或已变化的外部输入会按复制时的值补回。跨项目图片引用未导入时会整体阻止粘贴，不会清空图片。图片右键提供复制、粘贴和删除，空白画布右键可以新建图片。系统剪贴板同时保留图片和卡片数据；画布内粘贴保留提示词、参数与连线。拖入外部 PNG、JPEG、WebP（支持多张）或粘贴图片会新建卡片；网页图片需允许浏览器读取，否则可下载后拖入。删除确认支持 Enter 确认、Esc 取消，移入持久回收站，提示词、参数、版本和连线都保留；左侧可单张或全部恢复。撤销/重做恢复图内容和选择，并保留当前查看位置。拖动坐标由画布单独订阅，侧栏与无关图片不逐帧重渲染；松手后统一保存且只记一次撤销。失焦、刷新及迟到保存回执保留最终坐标，不降低原图清晰度。

独立浏览器中的原生生成使用本机 Codex 的 ChatGPT 登录与原生生图能力。账户不可用时，历史中会保留任务和具体原因。可以在本机 Codex 登录后重新预览。

## 四种运行方式

- **Codex 原生模式（默认）** 使用现有 Codex 账户及其额度。后台按画布保存执行会话，每次运行保存会话和轮次标识。目标像素按快照传递，历史中可以对照实际输出尺寸。
- **模拟模式**：本地产生带 MOCK 标识的测试图片，用于工作流和异常验证。它不会理解提示词，也不是实际 AI 生成，不调用生成模型。
- **手动模式**：创建等待回填的任务，导出提示词和主图，在用户选择的外部界面生成，再上传结果并确认对应任务。来源标记为「用户确认」。
- **Images API**：服务端适配器独立存在，默认关闭。当前没有经过验证的模型能力与总请求费用上界，真实 API 提交继续阻断。即使设置 `OPENAI_API_KEY`、打开开关并填写预算，也不会因此启用真实生成。后续需先完成模型及费用校准，再经明确授权做最小真实调用验收；mock 测试不能替代真实 API 验收。

Magpie 尚未接入，不会作为原生模式的隐式备用通道。插件不读取 Codex/ChatGPT 登录凭据、不调用私有额度接口，也不改变现有模型路由。独立 API 的密钥只从服务端环境读取，不通过浏览器输入、不写入项目或导出包。API 预算只约束本工具的请求，不能限制其他应用或保证供应商仅使用赠送额度。

## 历史和恢复

左侧「历史」默认显示生成记录。每次确认对应一条记录，同一批次的结果并列显示。可按提示词、图片名称或日期查找，点开记录即可定位卡片、查看参考图及实际尺寸。原生结果附有「查看 Codex 会话」入口。选择「图片」可按本画布或全部画布浏览素材与版本。窄屏一次展开一侧。

「全部画布」检索本机保存的素材，包括旧画布的图片。定位到其他画布后，可在那张画布上继续创作。

「备份 → 从备份恢复」会把备份中的卡片、原图、版本和任务记录加入当前画布，重映射标识并错开位置。恢复的生成记录仅用于查阅。已有画布从顶栏画布菜单进入。

每次确认创建独立 `runId` 和 `jobId`，快照中固定提示词、参数和输入资产版本。重复确认同一预览或幂等键返回同一任务。Codex 原生任务先持久化为 `awaiting_host`；宿主必须原子领取，且仅在返回 `canGenerate: true` 时调用一次原生图像工具。重复领取不能授权再次生图；同一结果回填保持幂等。

后台在提交前持久化任务与会话标识。回执中断后按原轮次或唯一任务标记查询，有结果时回填同一张卡片。暂时查不到的结果显示为待确认，也可在左侧历史手动核查。已取得的文件可从本地暂存恢复。

API 的未知请求保留预算，需核对供应商账单与结果后记录对账结论。取消已开始任务不保证原生工具或供应商停止，也不保证退还额度或退款；迟到结果仍会保留。

删除图片会移入回收站；历史素材和运行不随之删除，生成中的迟到结果也会保留。回收站内容包含在画布备份中。恢复保持原有卡片和素材关系，在空闲位置放回；已有卡片与新修改不被覆盖。旧版本中已移除卡片的图片可从现存素材恢复，无法凭空补回当时没有保存的布局和连线。撤销仅影响画布，不撤回已提交的生成。

## 插件与宿主接口

仓库提供插件清单、工作流技能、按需启动器和 MCP 服务器。打开入口可启动或复用本地画布；状态工具只读取项目和任务；原生任务的领取、回填与失败标记分别有明确工具边界，不能把整个 MCP 服务器称为只读。

画布、原始运行与执行会话的关联保存在本地数据库。备份保留运行溯源，执行权限与领取凭据仅存于本机。编辑使用已确认快照中的全部参考图，顺序与预览相同。旧任务仍可通过原有领取及回填协议处理。

此版提供独立浏览器画布及本地 Codex App Server 执行通道。接入细节见 [Codex 与 Magpie 接入说明](docs/codex-magpie-integration.md)。

## 开发和打包

以下命令面向源码开发和维护；插件使用流程由技能准备依赖和打开入口。

```bash
npm ci
npm run dev
```

生产构建使用 `npm run build`，再运行 `npm start`。`CANVEPP_URL` 可指定其他本地端口，仅接受 `http://127.0.0.1:<port>`。

```bash
npm run mcp
npm run package:plugin
```

插件包写入 `artifacts/`，不包含用户数据、依赖目录或凭据。首次使用由插件技能准备缺少的运行依赖。具体宿主安装状态应单独核验，打包成功不代表已安装或已完成原生生图验收。

```bash
npm run typecheck
npm test
npm run build
```

- `src/domain/`：宿主无关的图模型、类型/DAG 校验、失效传播、快照解析。
- `src/server/`：SQLite、本地资产存储、API 预算、运行服务和原生任务桥接。
- `src/components/`：React Flow 画布和创作界面。
- `src/app/api/`：带会话、来源和 CSRF 校验的本地 HTTP 接口。
- `scripts/local-service.mjs`：服务身份检查、启动锁、按需启动与复用。
- `scripts/canvas-agent.mjs`：打开并绑定当前对话、领取任务及原生结果回填。
- `scripts/mcp-server.mjs`：向宿主提供打开、状态和受限原生工作流工具。
- `docs/implementation-contract.md`：PRD 实施范围、UI 与接口合同。
- `docs/verification.md`：实际测试证据及未验收项。

源码开发中的 API 服务和 MCP 桥接必须使用同一个本地应用实例。不要同时对同一数据目录启动多个独立应用服务。
